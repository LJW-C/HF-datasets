# Dataset Generation Details

This document explains the current dataset generation pipeline and parameter settings. It assumes raw WAV files have already been generated by `generate_fldigi_wavs.py` or another equivalent recording process.

## 1. Input WAV Files

The script expects one folder per radio mode:

```text
raw_wav
+-- BPSK31
|   +-- BPSK31.wav
+-- BPSK63
|   +-- BPSK63.wav
+-- ...
```

The mode name is inferred from the folder name. The first `.wav` file inside the folder is used if the exact `{folder_name}.wav` file is not found.

## 2. Signal Preprocessing

For each WAV file:

1. Read the WAV file.
2. Convert stereo to mono if needed.
3. Convert integer PCM samples to `float32`.
4. Remove DC offset.
5. Trim leading and trailing silence.
6. Apply Hilbert transform to generate an analytic signal.
7. Mix the signal by `-carrier_hz`, normally `-1500 Hz`, to move the Fldigi audio signal to complex baseband.
8. Resample to `fs = 6000 Hz`.

The result is a long complex baseband IQ sequence for each mode.

## 3. HF Watterson Channel

The script applies the fading channel to the full preprocessed IQ sequence before slicing. This is important because slow Doppler spreads such as `0.1 Hz` need a long time axis to appear naturally.

The two-path channel form is:

```text
y[n] = (h1[n] x[n] + h2[n] x[n - d]) / sqrt(2)
```

Where:

```text
h1[n], h2[n] = independent complex Gaussian scatter fading taps
d             = path delay in samples
```

The fading taps are generated using a PathSim-style method:

```text
complex Gaussian noise
→ Gaussian FIR low-pass filter
→ complex fading tap
→ power normalization
```

The frequency spread parameter is interpreted as a `2-sigma bandwidth`.

## 4. Channel Profiles

| Profile | Paths | Delay | Frequency spread |
|---|---:|---:|---:|
| `good` | 2 | 0.5 ms | 0.1 Hz |
| `moderate` | 2 | 1.0 ms | 0.5 Hz |
| `poor` | 2 | 2.0 ms | 1.0 Hz |
| `flutter` | 2 | 0.5 ms | 10.0 Hz |
| `flat_0p2` | 1 | 0 ms | 0.2 Hz |
| `flat_1` | 1 | 0 ms | 1.0 Hz |
| `doppler` | 2 | 0.5 ms | 0.2 Hz + random 0..10 Hz offset |

`--ccir520-profile random` randomly selects one of:

```text
good, moderate, poor, flutter
```

## 5. Per-Sample Augmentation

For every output vector:

1. Select a channel profile.
2. Randomly slice `2048` complex IQ samples.
3. Normalize signal power.
4. Apply random frequency offset in `[-250, 250] Hz`.
5. Apply random phase offset in `[0, 2π]`.
6. Normalize signal power again.
7. Add complex AWGN at the selected SNR.

## 6. Output Files

| File | Type / shape | Description |
|---|---|---|
| `X.npy` | `complex64`, `[N, 2048]` | IQ vectors |
| `y.npy` | `int64`, `[N]` | mode labels |
| `snr_db.npy` | `int16`, `[N]` | SNR labels |
| `channel_profile.npy` | `int16`, `[N]` | channel profile labels |
| `mode_names.json` | JSON list | class index to mode name |
| `channel_profiles.json` | JSON list | channel index to profile name |
| `meta.json` | JSON object | generation metadata |

## 7. Default Dataset Size

For 17 modes:

```text
17 modes x 8 SNRs x 1200 vectors = 163,200 samples
```

For 18 modes:

```text
18 modes x 8 SNRs x 1200 vectors = 172,800 samples
```

## 8. Example Commands

Generate a mixed-profile dataset:

```powershell
python build_panoradio_like_dataset.py `
  --raw-root "E:\仿真\raw_wav" `
  --out-root "E:\仿真\panoradio_like_ccir520_npy" `
  --vectors-per-mode-snr 1200 `
  --ccir520-profile random
```

Generate only the poor-channel dataset:

```powershell
python build_panoradio_like_dataset.py `
  --raw-root "E:\仿真\raw_wav" `
  --out-root "E:\仿真\panoradio_like_poor" `
  --vectors-per-mode-snr 1200 `
  --ccir520-profile poor
```
